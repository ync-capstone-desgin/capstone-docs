# 팀원별 기획 문서 작성 규칙

`docs` 폴더는 세 명의 팀원이 각자 작성한 초기 기획 자료를 모으는 공간입니다. 아직 합의되지 않은 개인 아이디어를 공통 기획으로 표현하지 않습니다.

## 기본 구조

각 팀원은 `docs/<이름>/` 폴더를 하나 생성합니다.

```text
docs/
  member-a/
  member-b/
  member-c/
```

폴더 이름은 팀에서 알아볼 수 있도록 실명 영문 표기 또는 GitHub ID 중 하나로 통일합니다. 다른 팀원의 폴더 안에 직접 파일을 추가하거나 수정하지 않습니다.

## 문서 구성

개인 폴더 안의 파일 구성은 자유롭게 정할 수 있습니다. 다음 이름을 권장합니다.

| 파일 | 내용 |
|---|---|
| `proposal.md` | 문제 정의, 목표, 기능과 PoC 범위 |
| `questionnaire.md` | 기업 미팅에서 확인할 질문 |
| `schedule.md` | 분석, 설계, 개발, 검증 일정 |
| `research.md` | 참고자료와 조사 결과 |
| `meeting-notes.md` | 개인 미팅 기록과 의견 |

필요한 문서만 작성하며, 하나의 `proposal.md`에 모두 정리해도 됩니다.

## 작성 원칙

- 문서 상단에 작성자와 최종 수정일을 표시합니다.
- 확인되지 않은 내용은 사실처럼 단정하지 않고 `미팅 확인 필요`로 표시합니다.
- 다른 팀원의 의견을 인용할 때는 출처 또는 작성자를 표시합니다.
- 기업이 제공한 계약서, 인증서, 개인정보와 영업기밀은 저장소에 올리지 않습니다.
- API 키, 비밀번호, 토큰 등 보안정보를 커밋하지 않습니다.

## 브랜치와 커밋

- 브랜치 예시: `docs/<이름>-proposal`
- 커밋 예시: `docs: add <이름> proposal`
- 자신의 폴더 변경만 포함해 Pull Request를 생성합니다.

## 통합 단계

각자의 초안이 준비되면 팀 회의를 통해 공통점, 차이점과 추가 확인사항을 정리합니다. 통합 기획서는 별도 합의 후 생성하며, 그전까지 이 저장소의 개인 문서는 원본 그대로 유지합니다.
