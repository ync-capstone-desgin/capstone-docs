## 1. 미팅 목표

실제 업무 문제, 사용자, 데이터, 만료 규칙, PoC 범위와 성공 기준을 확인한다.

1. **먼저 듣는다.** 준비한 솔루션을 설명하기 전에 현행 업무와 최근 문제 사례를 먼저 듣는다.
2. **그다음 보여준다.** 프로토타입을 시연하고, 만들면서 가정으로 정한 부분이 실제 업무와 맞는지 확인한다. 빈칸 질문("며칠 전에 알림이 필요합니까?")보다 화면을 보며 묻는 질문("지금 90·30·7일 전인데 맞습니까?")이 답하기 쉽고 답이 구체적이다.
3. **범위를 정한다.** 계약·인증 만료와 알림만으로 충분한지, 그 외에 무엇이 꼭 필요한지 담당자가 직접 표시하게 한다.

프로토타입은 완성품이 아니라 **확인용 시안**이라는 점을 미팅 시작 때 분명히 말한다. 화면의 업체·계약·인증은 모두 가상의 샘플 데이터다.

### 질문 표 읽는 법

- **우선**: `A` 이번 미팅에서 반드시 확인 / `B` 가능하면 확인 / `C` 후속 확인 가능
- **현재 프로토타입**: 확인되지 않아 가정으로 정하고 구현한 방식. 이것을 보여주고 맞는지 묻는다.
- **답에 따라 바뀌는 것**: 답을 받으면 무엇을 고쳐야 하는지. 미팅 자리에서 "바로 됩니다 / 일정 조정이 필요합니다"를 판단하는 데 쓴다 ([10장](#10-미팅-후-반영-계획)).
- **(옛 N번)**: 이전 질문지(32문항)의 번호. 팀원 문서에서 옛 번호를 참조한 경우를 위해 남긴다.

## 2. 60분 진행안

| 시간 | 내용 | 진행 주체 | 목표 |
|---|---|---|---|
| 0~5분 | 참석자 소개와 목적 | 프로젝트팀 | 오늘 확인할 것 공유, "확인용 시안"임을 설명 |
| 5~20분 | 현행 업무와 문제 설명 ([3장](#3-현행-업무와-문제-먼저-듣기)) | 한국농산 | 실제 흐름과 어려움 이해. 프로젝트팀은 듣고 기록 |
| 20~30분 | 프로토타입 시연 | 프로젝트팀 | 대시보드 → 실시간 알림 → 메일 → 갱신 → 알림 자동 완료 (사용 설명서 11장) |
| 30~38분 | 범위 확인 ([4장](#4-범위-확인-계약인증-만료와-알림만-있으면-되는가)) | 공동 | 추가 기능 우선순위표 작성 |
| 38~53분 | 세부 질문 ([5장](#5-세부-질문)) | 공동 | 우선순위 A부터, 해당 화면을 띄워 놓고 질문 |
| 53~60분 | 결정사항·자료 요청·후속조치 ([7장](#7-자료-요청-목록)·[8장](#8-미팅-종료-체크리스트)) | 프로젝트팀 | 담당자와 기한 확정 |

**시연 중 메모할 것**: 담당자가 화면을 보며 "이건 우리랑 달라요", "이건 필요 없어요", "이게 있으면 좋겠다"고 말하는 순간을 그대로 받아 적는다. 질문보다 이 반응이 더 정확한 요구사항이다.

## 3. 현행 업무와 문제 (먼저 듣기)

시연 전에 묻는다. 프로토타입을 먼저 보면 답이 화면에 끌려가므로, 이 장은 **열린 질문**으로 둔다.

| ID | 우선 | 질문 | 확인 목적 |
|---|---|---|---|
| W-01 | A | 협력업체 업무는 어떤 부서와 담당자가 수행합니까? (옛 1번) | 사용자와 부서 |
| W-02 | A | 협력업체 관리 실무 담당자는 총 몇 명이며, 1인 전담입니까 아니면 다른 업무와 겸임·분담하고 있습니까? (옛 2번) | 사용자 수, 담당자 구조 |
| W-03 | A | 가장 시간이 많이 들거나 누락 위험이 큰 업무는 무엇입니까? (옛 3번) | 핵심 문제 |
| W-04 | A | 업체 등록부터 계약·인증·발주·납기관리까지 전체 절차는 어떻게 됩니까? (옛 4번) | 업무 흐름도 |
| W-05 | A | 최근 1년 안에 만료 누락, 자료 검색 지연 또는 납기 확인 문제 사례가 있습니까? 있다면 어떤 결과(거래 중단, 재인증 비용, 과태료 등)였습니까? (옛 5번) | 문제의 크기, 발표 근거 |
| W-06 | A | 지금은 만료를 누가, 어떤 방법(엑셀 정렬, 달력 메모, 기억 등)으로 챙깁니까? 한 달에 몇 시간 정도 씁니까? | 도입 효과 측정 기준(전후 비교) |

## 4. 범위 확인: 계약·인증 만료와 알림만 있으면 되는가

현재 프로토타입은 **"계약·인증 만료를 놓치지 않게 하는 것"** 하나에 집중했다. 시연 직후, 이 방향이 맞는지와 그 외에 무엇이 필요한지를 확인한다.

### 4.1 핵심 문제 확인

| ID | 우선 | 질문 | 확인 목적 |
|---|---|---|---|
| S-01 | A | 이번 PoC가 반드시 해결해야 할 문제 한 가지는 무엇입니까? 시연한 화면이 그 문제를 해결합니까? 가장 큰 불편이 **만료 누락**이 맞습니까, 아니면 **자료 찾기**나 **발주·납기 확인**이 더 큽니까? (옛 6번) | 프로젝트 방향 확정 |
| S-02 | A | 이 시스템을 매일 쓸 사람은 누구이고, 가끔 조회만 할 사람은 누구입니까? | 역할별 화면·권한 |

- S-13·S-14에 "꼭 필요"가 나오면 다음 개발 우선순위로 올린다. 엑셀 일괄 등록은 실제 데이터를 넣어 시범 운영하려면 사실상 필요하다.
- S-15에 "꼭 필요"가 나오면 범위가 크게 늘어난다. [5.6 발주·납기와 연동](#56-발주납기와-연동)의 질문으로 조회만인지, 데이터 출처가 어디인지부터 확인한다.
- S-19·S-20은 12주 PoC 범위를 넘는다. "꼭 필요"라도 PoC 이후 단계로 제안하고 합의한다.

## 10. 미팅 후 반영 계획

답을 받은 뒤 아래 순서로 반영한다. 프로토타입은 규칙을 한 곳에 모아 두었기 때문에 대부분 설정값이나 한두 파일 수정으로 끝난다.

| 답의 종류 | 예 | 수정 범위 | 예상 작업량 |
|---|---|---|---|
| 설정값 변경 | 알림 시점, 만료예정 기간, 점검 시각 | 알림 설정 화면 또는 설정 파일 | 즉시 |
| 판정 규칙 변경 | D-DAY 처리, 만료 후 재알림, 제외 조건 | `ExpiryPolicy`, `NotificationScanService` | 반나절 |
| 항목 추가 | 업체 주소·품목, 계약 금액, 해지 통보 기한 | 마이그레이션 + 엔티티·DTO + 등록 화면 | 1~2일 |
| 기능 추가 | 엑셀 일괄 등록, 파일 업로드, 요약 메일, 발주·납기 조회 | 새 기능 단위 개발 | 기능당 3~5일 |
| 구조 변경 | 인증이 품목 단위, 부서별 권한 | 데이터 모델·권한 재설계 | 1주 이상 → 범위·일정 재협의 |
