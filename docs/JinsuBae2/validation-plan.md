## 1. 검증 목적

PoC가 핵심 업무 문제를 해결할 가능성이 있는지 확인한다. 기능 수보다 만료 대상의 정확성, 정보 조회 흐름과 실제 담당자의 사용 가능성을 우선 평가한다.

## 2. 검증 범위

- 협력업체 등록·검색·상세 조회
- 계약 및 인증 등록·수정
- 만료 상태 계산
- 알림 대상 생성
- 대시보드 집계
- 사용자 시나리오 수행

## 3. 샘플 데이터 기준

| 데이터 | 권장 수량 | 구성 |
|---|---:|---|
| 협력업체 | 20건 이상 | 정상·중지 등 다양한 상태 |
| 계약 | 30건 이상 | 정상, D-90, D-30, D-7, 만료, 무기한 후보 |
| 인증 | 30건 이상 | 여러 인증 종류와 경계일 포함 |
| 사용자 | 3명 이상 | 관리자·담당자·조회 사용자 후보 |
| 알림 | 자동 생성 | 기준일별 중복·실패·확인 상태 포함 |

모든 데이터는 가공하거나 비식별 처리한다.

## 6. 사용자 검증 질문

- 현재 방식보다 필요한 정보를 더 빨리 찾을 수 있는가
- 화면에 불필요하거나 누락된 정보는 무엇인가
- 만료 예정 상태와 처리상태가 이해하기 쉬운가
- 실제 업무 순서와 화면 이동 순서가 맞는가
- 알림이 너무 많거나 부족할 가능성이 있는가
- 실제 사용을 위해 반드시 추가해야 할 기능은 무엇인가

## 7. 종료 조건

- Must 기능의 핵심 시나리오를 시연할 수 있다.
- 알려진 중대 오류가 없다.
- 미확정 요구사항과 PoC 제외 범위가 문서화되어 있다.
- 기업 또는 지도교수 피드백과 후속 개선안이 기록되어 있다.
