## 1. 문서 목적

첫 미팅 질문지는 "무엇을 만들지"를 묻는 열린 질문이었다. 프로토타입을 만들면서 확인되지 않은 부분은 **가정으로 정하고 구현**했다. 이 문서는 그 가정을 기업 담당자에게 **화면으로 보여주고 맞는지 확인**하기 위한 질문지다.

- 질문마다 **현재 프로토타입 방식**을 먼저 보여주고, 맞는지·다른지를 묻는다. 빈칸 질문보다 답하기 쉽고, 답이 구체적으로 나온다.
- 각 질문에 **답에 따라 바뀌는 것**을 적어, 미팅 직후 수정 범위와 일정을 바로 판단할 수 있게 한다.
- 우선순위는 `A`(이번 미팅에서 반드시 확인), `B`(가능하면 확인), `C`(후속 확인 가능)로 표시한다.

## 2. 진행 방식 (60분)

| 시간 | 내용 | 비고 |
|---|---|---|
| 0~5분 | 목적 공유: "만든 것을 보여드리고, 실제 업무와 다른 점을 찾는 자리" | 완성품이 아니라 확인용 시안임을 먼저 말한다 |
| 5~15분 | 프로토타입 시연 (사용 설명서 11장 시나리오) | 대시보드 → 실시간 알림 → 메일 → 갱신 → 알림 자동 완료 |
| 15~25분 | **3장 범위 확인** | 가장 중요. 이 답에 따라 나머지 질문의 비중이 달라진다 |
| 25~50분 | 4~9장 세부 질문 | 우선순위 A부터. 해당 화면을 띄워 놓고 묻는다 |
| 50~60분 | 결정사항·자료 요청·다음 일정 정리 | 11장 체크리스트 |

**시연 중 메모할 것**: 담당자가 화면을 보며 "이건 우리랑 달라요", "이건 필요 없어요", "이게 있으면 좋겠다"고 말하는 순간을 그대로 받아 적는다. 질문보다 이 반응이 더 정확한 요구사항이다.

## 3. 범위 확인: 계약·인증 만료와 알림만 있으면 되는가 (가장 중요)

현재 프로토타입은 **"계약·인증 만료를 놓치지 않게 하는 것"** 하나에 집중했다. 이 방향이 맞는지, 그 외에 무엇이 필요한지를 가장 먼저 확인한다.

### 3.1 핵심 문제 확인

| ID | 우선 | 질문 | 확인 목적 |
|---|---|---|---|
| S-01 | A | 시연한 화면이 실제로 겪는 문제를 해결합니까? 가장 큰 불편이 **만료 누락**이 맞습니까, 아니면 **자료 찾기**나 **발주·납기 확인**이 더 큽니까? | 프로젝트 방향 확정 |
| S-02 | A | 최근 1년 안에 계약·인증 만료를 놓쳐 생긴 실제 사례가 있습니까? 있다면 어떤 결과(거래 중단, 재인증 비용, 과태료 등)였습니까? | 문제의 크기, 발표 때 쓸 근거 |
| S-03 | A | 지금은 만료를 누가, 어떤 방법(엑셀 정렬, 달력 메모, 기억 등)으로 챙깁니까? 한 달에 몇 시간 정도 씁니까? | 도입 효과 측정 기준(전후 비교) |
| S-04 | A | 이 시스템을 매일 쓸 사람은 누구입니까? (구매팀·품질팀·영업팀 중) 몇 명입니까? | 사용자와 권한 설계 |

| S-12 | 만료 전 자동 알림 (화면·이메일) | 구현 | ☐ | ☐ | ☐ |
| S-13 | 계약서·인증서 **원본 파일 보관**(업로드·다운로드) | 링크만 저장 | ☐ | ☐ | ☐ |
| S-14 | 기존 엑셀 대장을 **한 번에 올리기**(일괄 등록) | 미구현 | ☐ | ☐ | ☐ |
| S-15 | **발주·납기** 현황 조회 (업체별 발주, 납기 지연) | 미구현 | ☐ | ☐ | ☐ |
| S-16 | 계약 금액·조건 관리 | 미구현 | ☐ | ☐ | ☐ |

| S-19 | 협력업체가 직접 인증서를 **제출하는 외부 화면** | 미구현 | ☐ | ☐ | ☐ |
| S-20 | ERP·그룹웨어와 **자동 연동** | 미구현 | ☐ | ☐ | ☐ |
| S-21 | 문자·카카오톡 알림 | 미구현 (이메일만) | ☐ | ☐ | ☐ |
| S-22 | 모바일 화면 | 미구현 (PC 기준) | ☐ | ☐ | ☐ |

**답에 따라 바뀌는 것**

- S-13·S-14에 "꼭 필요"가 나오면 다음 개발 우선순위로 올린다. 엑셀 일괄 등록은 실제 데이터를 넣어 시범 운영하려면 사실상 필요하다.
- S-15에 "꼭 필요"가 나오면 범위가 크게 늘어난다. 조회만인지, 등록·수정까지인지, 데이터 출처가 ERP인지부터 확인한다(9장 D-05).
- S-19·S-20은 12주 PoC 범위를 넘는다. "꼭 필요"라도 PoC 이후 단계로 제안하고 합의한다.

| V-04 | A | 업체마다 **내부 담당자 1명** | 담당이 업체 단위입니까, 계약·인증 단위입니까? 부서별로 담당자가 따로 있습니까(구매 담당, 품질 담당)? | 담당자 구조, 알림 수신자 |

| ID | 우선 | 현재 프로토타입 방식 | 질문 | 답에 따라 바뀌는 것 |

| C-01 | A | 계약번호, 계약명, 시작일, 종료일, 자동연장 여부, 담당자, 계약서 링크 | 관리하는 계약 종류는? (납품 기본계약, 물류 위탁, 품질보증 협약 등) 종류마다 관리 항목이 다릅니까? | 계약 유형 코드, 항목 |
| C-02 | A | 종료일이 없으면 **무기한 계약**으로 보고 알림 대상에서 제외 | 종료일이 없는 계약이 실제로 있습니까? 있다면 주기적으로 점검해야 합니까? | 만료 판정, 정기 점검 알림 |
| C-03 | A | **자동연장** 여부는 기록만 하고, 자동연장 계약도 종료일 기준으로 똑같이 알림 | 자동연장 계약도 만료 전에 알림이 필요합니까? (해지 통보 기한을 놓치지 않기 위해 등) 해지 통보 기한이 계약마다 있습니까? | 자동연장 알림 규칙, "해지 통보 기한" 항목 추가 |
| C-04 | A | 갱신 시 **새 계약을 등록**하고 이전 계약은 "갱신완료" 이력으로 보관 | 실제 갱신은 새 계약서를 쓰는 방식입니까, 기존 계약의 기간만 늘리는 방식(변경 계약)입니까? 과거 계약 이력을 봐야 합니까? | 갱신 기능 방식 |
| C-05 | B | 같은 업체에 같은 계약번호가 있으면 **저장은 하고 경고** | 계약번호 체계가 있습니까? 중복이 절대 없어야 합니까, 있을 수 있습니까? | 중복 경고 → 차단 여부 |
| C-06 | B | 계약 금액은 관리하지 않음 | 계약 금액·단가·결제 조건도 관리해야 합니까? 민감정보라 접근 제한이 필요합니까? | 금액 항목, 권한 |
| C-07 | C | 계약 상대는 업체 1곳 | 여러 업체와 함께 맺는 계약(공동계약)이 있습니까? | 계약-업체 관계 |

## 6. 인증

> 시연 화면: 인증 관리 목록 → 인증 종류 필터 → 만료일 없는 인증(확인 필요)

| ID | 우선 | 현재 프로토타입 방식 | 질문 | 답에 따라 바뀌는 것 |
|---|---|---|---|---|
| E-01 | A | 인증 종류 예시: HACCP, GAP, 유기농산물, 무농약농산물, ISO 9001, ISO 22000 | 실제로 관리하는 인증 종류는 무엇입니까? 빠진 것(친환경, 이력추적, 수출 관련 등)과 필요 없는 것은? | 인증 종류 기준정보 |
| E-02 | A | 인증은 **업체 단위**로 등록 | 인증이 업체 단위입니까, **품목·농가·작업장 단위**입니까? (예: GAP은 품목·농가별로 따로 받는 경우) | 인증-업체 관계, 품목 항목 추가 (구조 변경 가능성 큼) |
| E-03 | A | 만료일이 없으면 "확인 필요"로 분류 | 만료일이 없는 인증이 있습니까? 인증 종류별 유효기간이 정해져 있습니까? (예: 발급일로부터 N년) | 만료일 자동 계산, 확인 필요 규칙 |
| E-04 | B | 인증 종류·인증번호가 같으면 경고 | 인증번호로 인증을 구분할 수 있습니까? 갱신하면 번호가 바뀝니까? | 중복 규칙, 갱신 방식 |
| E-05 | B | 갱신 기한은 만료일 하나로만 판단 | 갱신 심사 신청 기한이 만료일보다 한참 앞입니까? (예: 만료 3개월 전까지 신청) | 알림 시점, "신청 기한" 항목 추가 |
| E-06 | C | 인증서는 링크만 저장 | 인증서 사본을 업체에서 어떻게 받습니까? (이메일, 우편, 인증기관 사이트 조회) | 문서 수집 방법, 외부 제출 화면 필요성 |

| R-06 | C | 거래중이 아닌 업체의 계약·인증은 알림 제외 | 거래중지 업체도 인증 만료를 챙겨야 합니까? (거래 재개 대비) | 알림 제외 조건 |

## 12. 미팅 후 반영 계획

답을 받은 뒤 아래 순서로 반영한다. 프로토타입은 규칙을 한 곳에 모아 두었기 때문에, 대부분 설정값이나 한두 파일 수정으로 끝난다.

| 답의 종류 | 예 | 수정 범위 | 예상 작업량 |
|---|---|---|---|
| 설정값 변경 | 알림 시점, 만료예정 기간, 점검 시각 | 알림 설정 화면 또는 설정 파일 | 즉시 |
| 판정 규칙 변경 | D-0 처리, 만료 후 재알림, 제외 조건 | `ExpiryPolicy`, `NotificationScanService` | 반나절 |
| 항목 추가 | 업체 주소·품목, 계약 금액, 해지 통보 기한 | 마이그레이션 + 엔티티·DTO + 등록 화면 | 1~2일 |
| 기능 추가 | 엑셀 일괄 등록, 파일 업로드, 요약 메일 | 새 기능 단위 개발 | 기능당 3~5일 |
| 구조 변경 | 인증이 품목 단위, 부서별 권한 | 데이터 모델·권한 재설계 | 1주 이상 → 범위·일정 재협의 |
