# 협력업체 통합관리 PoC 시스템 설계 초안

- 작성자: JinsuBae2
- 최종 수정일: 2026-09-22
- 상태: 초안

## 1. 설계 목적

협력업체, 계약, 인증과 만료 알림의 핵심 흐름을 검증할 수 있는 최소 구조를 정의한다. 특정 기술이나 기업 시스템 연동은 아직 확정하지 않고, 미팅 후 변경하기 쉬운 논리적 경계를 우선 설계한다.

## 2. 설계 원칙

- 1차 PoC는 협력업체, 계약, 인증과 만료 알림에 집중한다.
- 발주·납기는 조회 중심의 확장 영역으로 분리한다.
- 업무 규칙과 알림 기준은 코드에 고정하지 않고 설정 가능하게 설계한다.
- 파일 원본보다 메타데이터 관리와 업무 흐름 검증을 우선한다.
- 실제 개인정보 대신 비식별 샘플 데이터를 사용한다.
- 외부 ERP, 이메일과 클라우드 연동은 인터페이스만 고려하고 구현 범위는 미팅 후 결정한다.

## 3. 논리 구조

```text
[사용자]
   |
   v
[웹 화면]
   |-- 대시보드
   |-- 협력업체 관리
   |-- 계약 관리
   |-- 인증 관리
   |-- 만료 예정 조회
   |-- 발주·납기 조회 선택
   |
   v
[애플리케이션 API]
   |-- 협력업체 서비스
   |-- 계약 서비스
   |-- 인증 서비스
   |-- 만료 판정 서비스
   |-- 알림 서비스
   |-- 파일 메타데이터 서비스
   |
   +-------------------+
   |                   |
   v                   v
[관계형 DB]       [파일 저장소 선택]
   |
   v
[정기 실행 작업]
   |-- 만료 대상 계산
   |-- 알림 대상 생성
   |-- 알림 이력 기록
```

## 4. 구성요소 책임

| 구성요소 | 책임 | 현재 상태 |
|---|---|---|
| 웹 화면 | 사용자 입력, 검색, 현황 시각화 | 설계 가능 |
| 협력업체 서비스 | 업체 기본정보와 상태 관리 | 설계 가능 |
| 계약 서비스 | 계약기간, 상태, 담당자와 문서 참조 관리 | 필드 확인 필요 |
| 인증 서비스 | 인증 종류, 유효기간과 갱신 이력 관리 | 종류·규칙 확인 필요 |
| 만료 판정 서비스 | 기준일에 따른 정상·예정·만료 상태 계산 | 기준일 확인 필요 |
| 알림 서비스 | 알림 대상 생성, 발송 요청과 처리 이력 관리 | 채널·수신자 확인 필요 |
| 발주·납기 서비스 | 업체별 발주 및 납기 현황 조회 | 포함 범위 확인 필요 |
| 파일 저장소 | 계약서·인증서 파일 보관 | 보안정책 확인 필요 |

## 5. 핵심 데이터 흐름

### 계약 또는 인증 등록

1. 사용자가 협력업체를 선택한다.
2. 계약 또는 인증의 기본정보와 유효기간을 입력한다.
3. 시스템이 필수값과 날짜 순서를 검증한다.
4. 데이터와 선택적인 파일 참조를 저장한다.
5. 현재 날짜를 기준으로 만료 상태를 계산해 표시한다.

### 만료 대상 생성

1. 정기 실행 작업이 활성 계약과 인증을 조회한다.
2. 항목별 만료일과 알림 기준일을 비교한다.
3. 조건에 해당하면 중복 여부를 확인한다.
4. 새로운 알림 대상을 생성하고 이력을 남긴다.
5. 대시보드에 표시하고, 확정된 채널이 있으면 발송을 요청한다.

## 6. 오류 처리 원칙

- 종료일이 시작일보다 빠르면 저장하지 않는다.
- 필수 날짜가 없으면 만료 판정 대상에서 제외하고 확인 필요 상태로 표시한다.
- 동일 업체와 문서번호의 중복 등록을 경고한다.
- 알림 발송 실패와 업무 데이터 저장 실패를 분리해 기록한다.
- 외부 연동 실패가 핵심 데이터 등록을 막지 않도록 재시도 가능한 구조로 둔다.

## 7. 보안 초안

- PoC에는 비식별 샘플 데이터만 사용한다.
- 계정, 토큰과 실제 문서를 Git에 저장하지 않는다.
- 사용자 인증이 필요하면 최소한 관리자와 일반 사용자 역할을 구분한다.
- 파일 접근은 DB 레코드 권한과 동일한 기준으로 제한한다.
- 실제 서비스 전환 전 접근 로그, 백업, 암호화와 보관기간을 확정한다.

## 8. 기술 결정 보류 항목

- 프론트엔드 및 백엔드 프레임워크
- 데이터베이스 제품과 배포 방식
- 파일 저장 위치
- 이메일·문자·메신저 알림 채널
- 기업 내부 시스템 및 ERP 연동 방식
- 온프레미스 또는 클라우드 배포 여부
