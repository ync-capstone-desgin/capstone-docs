# 한국농산 협력업체 통합관리 PoC 일정표

## 1. 일정 운영 원칙

본 일정은 첫 미팅 이전에 작성한 12주 기준 초안이다. 실제 학사일정, 팀 인원, 기업 검토 가능일과 데이터 제공 시점에 따라 조정한다. 개발 시작 전에 문제, 데이터, PoC 범위와 성공 기준을 먼저 확정한다.

## 2. 12주 일정 초안

| 주차 | 단계 | 주요 작업 | 산출물 | 기업 협조사항 |
|---|---|---|---|---|
| 1주 | 착수 | 기업 미팅, 현행 업무와 문제 확인 | 회의록, 요구사항 초안 | 담당자 인터뷰 |
| 2주 | 분석 | 자료 흐름, 데이터 항목, 사용자 역할 분석 | 업무 흐름도, 데이터 목록 | 샘플 자료 제공 |
| 3주 | 범위 확정 | 우선순위와 제외 범위, 성공 기준 합의 | PoC 범위서, 검증 기준 | 범위 검토·승인 |
| 4주 | 설계 | 화면 흐름, 데이터 구조, 시스템 구성 설계 | 와이어프레임, ERD 초안 | 화면 초안 피드백 |
| 5주 | 기반 개발 | 프로젝트 환경, 사용자와 협력업체 기본 기능 | 실행 가능한 초기 버전 | 필요 시 계정 정책 확인 |
| 6주 | 핵심 개발 | 계약 및 인증 등록·조회 기능 | 계약·인증 관리 기능 | 항목명과 규칙 확인 |
| 7주 | 핵심 개발 | 만료 판정, 대시보드, 검색·필터 | 만료 현황 화면 | 만료 기준 검토 |
| 8주 | 연계 개발 | 알림 이력과 발주·납기 최소 조회 기능 | 통합 시나리오 | 알림 대상·채널 확인 |
| 9주 | 통합 테스트 | 샘플 데이터 입력, 기능·예외 테스트 | 테스트 결과서 | 샘플 데이터 검증 |
| 10주 | 사용자 검증 | 실무자 시연과 사용성 평가 | 피드백 목록, 개선 우선순위 | 시연 참석·평가 |
| 11주 | 개선 | 중요 오류와 사용성 문제 보완 | PoC 후보 버전 | 변경사항 확인 |
| 12주 | 최종화 | 최종 시연, 결과와 서비스 전환안 정리 | PoC, 최종 보고서, 로드맵 | 결과 확인 |

## 3. 주요 마일스톤

| 마일스톤 | 목표 시점 | 완료 조건 |
|---|---|---|
| M1 요구사항 기준선 | 3주차 종료 | 필수 기능, 제외 범위, 성공 기준 합의 |
| M2 설계 검토 | 4주차 종료 | 주요 화면과 데이터 구조 피드백 반영 |
| M3 핵심 기능 완료 | 8주차 종료 | 협력업체, 계약, 인증, 만료 알림 시나리오 동작 |
| M4 사용자 검증 | 10주차 종료 | 실무자 시연 및 피드백 확보 |
| M5 최종 PoC | 12주차 종료 | 핵심 시나리오 검증과 결과 보고 완료 |

## 4. 변경 관리

- 새 기능 요청은 필수, 중요, 후속 검토로 구분한다.
- 필수 범위 추가 시 일정 또는 기존 범위 조정 여부를 함께 결정한다.
- 기업의 데이터 제공이 지연될 경우 팀이 만든 비식별 샘플 데이터로 개발하되, 실제 데이터 검증 일정을 별도로 확보한다.
- 매주 완료 항목, 다음 작업, 위험 요소와 필요한 협조사항을 기록한다.
