# 한국농산 협력업체 계약·인증 통합관리 및 만료 대응 기획안 (v3)

- 작성자: 조대성 (GitHub: @Rinhaze)
- 최종 수정일: 2026-09-29
- 상태: 초안
- 이력: v1(2026-09-22) → v2(검토단 의견 반영) → v3(팀 공통 주제와 범위 정렬)

> 개인 제안 초안이며 팀 합의 전 상태다. 확인되지 않은 내용은 `미팅 확인 필요`로 표시한다.

## 1. 배경과 문제
한국농산의 협력업체 계약, 인증, 발주·납기 자료가 부서와 파일별로 흩어져 있다. 이 때문에 다음 문제가 생길 수 있다고 본다(`미팅 확인 필요`).

- 계약·인증 만료를 놓쳐 거래 차질이나 품질 리스크가 생긴다.
- 만료가 다가온 것을 알아도 누가 언제 갱신하는지 추적되지 않는다.
- 담당자가 바뀌면 진행 중인 갱신 업무가 인수인계되지 않는다.

## 2. 목표
팀 공통 주제(capstone-docs README 3장)를 따른다.

1. 협력업체 기본정보와 계약·인증 자료를 업체 단위로 통합한다.
2. 계약·인증 유효기간으로 만료 상태를 자동으로 판정하고, 담당자에게 알린다.
3. **만료 알림에서 끝내지 않고, 갱신 업무가 완료될 때까지 추적한다.** (이 기획안의 차별점)
4. 발주·납기는 조회 수준으로 필요성과 관리 방안을 검토한다.

## 3. 사용자와 권한
팀원 프로토타입(JinsuBae2)과 같은 3개 역할로 맞춘다.

| 역할 | 권한 | 미팅 확인 |
|---|---|---|
| ADMIN (관리자) | 전체 기능, 사용자·기준정보 관리 | 실제 관리 부서 |
| MANAGER (담당자) | 조회, 업체·계약·인증 등록·수정, 갱신 업무 처리 | 구매·품질 등 담당 부서 |
| VIEWER (조회자) | 조회만 | 조회 범위 |

## 4. 범위
### PoC 필수 (Must)
| 기능 | 내용 | 참고: JinsuBae2 FR |
|---|---|---|
| 협력업체 관리 | 등록·조회·수정·검색, 거래상태(거래중·중지 등, 종류는 `미팅 확인 필요`) | FR-001~003 |
| 업체 상세 | 업체별 계약·인증·갱신 업무를 한 화면에서 조회 | FR-004 |
| 계약 관리 | 계약번호, 계약명, 시작·종료일, 자동연장 여부, 내부 담당자 | FR-005 |
| 인증 관리 | 인증 종류, 인증번호, 인증기관, 발급·만료일, 내부 담당자 | FR-006 |
| 만료 판정 | 오늘 날짜와 만료일을 비교해 상태 계산 (6장) | FR-007 |
| 만료 목록·대시보드 | 기간·유형·담당자·처리상태 필터, 요약 집계 | FR-008~009 |
| 알림 대상 생성 | D-90·30·7에 알림 생성, 같은 대상·기준에는 중복 생성 안 함 | FR-010 |
| **갱신 업무** | 알림이 생성되면 갱신 업무를 만들고 담당자·기한·처리상태를 관리하며, 새 계약·인증을 등록하면 완료 처리 | 신규 제안 |

### 여유가 되면 추가 (Should)
- 로그인과 역할별 권한 (FR-013)
- 계약서·인증서 파일 첨부 또는 링크 연결 (FR-012)
- 알림 이력: 생성·발송·확인 상태 (FR-011)
- 변경 이력: 등록·수정자, 수정일, 변경 전후 값
- 이메일 알림 발송

### 필요성 검토 (Could)
- 엑셀 일괄 등록 (FR-014)
- 발주·납기 **조회**: 업체별 발주번호, 품목, 수량, 납기일, 상태 (FR-015)

### 이번 범위에서 제외
- 입고·부분 입고·반품·잔량 관리 (발주·납기 범위가 확정되면 다시 검토)
- ERP 연동, 전자계약·결재, 협력업체 포털, 문자·카카오톡 알림, 업체 평가·등급
- AI 문서 추출 (7장의 후속 검토로만 둠)

## 5. 핵심 흐름
1. 담당자가 협력업체를 등록한다.
2. 업체에 계약 또는 인증과 유효기간을 등록한다.
3. 매일 실행되는 작업이 만료 상태를 계산하고, D-90·30·7에 도달한 대상에 알림과 갱신 업무를 만든다.
4. 담당자가 갱신 업무를 `진행`으로 바꾸고 처리 내용을 기록한다.
5. 새 계약·인증을 등록하면 이전 건은 `갱신됨`이 되고 업무는 `완료`된다.
6. 관리자가 대시보드에서 미처리 업무와 만료 건을 확인한다.

## 6. 상태와 규칙
날짜로 계산하는 **만료 상태**와 사람이 처리하는 **갱신 업무 상태**를 분리한다.

**만료 상태 (계산값, 저장하지 않음)**

| 조건 | 상태 |
|---|---|
| 만료일 없음 | 확인 필요 |
| 만료일 < 오늘 | 만료 |
| 오늘 ≤ 만료일 ≤ 오늘 + 90일 | 만료 예정 (D-day 표시) |
| 만료일 > 오늘 + 90일 | 정상 |
| 새 건이 등록되어 대체됨 | 갱신됨 |

**갱신 업무 상태:** 미착수 → 진행 → 완료 / 보류(사유 필수). "기한 초과"는 저장하지 않고 날짜로 계산해 표시한다.

**규칙**
- 알림 기준일은 D-90·30·7로 하고 설정값으로 관리한다. 실제 기준은 `미팅 확인 필요`.
- 오늘 만료되는 건은 `만료 예정 D-0`으로 본다. 경계 규칙은 `미팅 확인 필요`.
- 중복방지키는 `대상유형 + 대상ID + 기준일수`로 하고 UNIQUE 제약을 건다. 작업을 다시 실행해도 알림은 한 번만 생긴다.
- 자동연장 계약은 종료일에 만료로 처리하지 않고 `확인 필요`로 표시한다(`미팅 확인 필요`).
- 종료일이 시작일보다 빠르면 저장하지 않는다. 같은 업체에 같은 인증번호가 있으면 경고한다.
- 날짜와 시간은 KST, 날짜 형식은 ISO 8601로 통일한다.

## 7. 인증 종류와 도메인 확인
한국농산의 업종에 맞춰 다음을 예시로 들고, 실제 목록은 미팅에서 확정한다(`미팅 확인 필요`).

- HACCP (식품안전관리인증)
- GAP (농산물우수관리인증)
- 친환경 농산물 인증 (유기농·무농약)
- 그 밖에 협력업체와 맺은 품질보증 계약서, 거래 계약서 등

**AI 활용 (후속 검토):** 인증서에서 인증번호·유효기간을 추출하는 기능은 PoC 이후에 검토한다. 회사 자료를 외부로 보내지 않도록 로컬 처리를 우선하고, 추출값은 사람이 확인한 뒤 확정한다.

## 9. 기술 스택 (개인 프로토타입)
| 영역 | 선택 |
|---|---|
| 서버 | Python 3.12+, Django 5.2 LTS + Django REST Framework |
| DB | PostgreSQL (Docker Compose) |
| 화면 | React + TypeScript |
| 정기 작업 | Django 관리 명령 + cron |
| 테스트 | pytest (만료 경계일, 중복 알림, 권한) |

팀원 프로토타입은 Spring Boot를 쓴다. 통합 개발 저장소의 스택은 팀이 따로 결정한다. 그때 비교할 수 있도록 **API 경로와 상태값 이름은 팀 프로토타입과 최대한 맞춘다.**

## 11. 검증
**샘플 데이터 (비식별):** 업체 20건 이상, 계약 30건 이상, 인증 30건 이상. 정상, D-90, D-30, D-7, D-0, 만료, 자동연장, 만료일 없음 사례를 섞는다.

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| T-01 | D-90·30·7·0 항목 | 각 기준일 알림 대상에 정확히 포함 |
| T-02 | 정기 작업 두 번 실행 | 알림·갱신 업무 중복 0건 |
| T-03 | 종료일이 시작일보다 빠른 계약 | 저장 차단과 오류 안내 |
| T-04 | 새 인증 등록 | 이전 인증이 `갱신됨`, 업무가 `완료` |
| T-05 | 보류 처리 | 사유 없이는 저장 차단 |
| T-06 | 업체 상세 조회 | 해당 업체의 계약·인증·업무만 표시 |
| T-07 | 대시보드 집계 | 원본 데이터 건수와 일치 |
| T-08 | VIEWER로 수정 시도 (Should) | 화면과 API 모두 차단 |

**성공 기준 초안:** 만료 판정 정확도 100%, 중복 알림 0건, 핵심 시나리오 성공률 90% 이상, 실무자 사용성 평가 5점 중 4점 이상. 수치는 미팅 후 확정한다.

## 12. 위험
| 위험 | 대응 |
|---|---|
| 실제 업무와 가설이 다름 | 인터뷰와 화면 검토를 마친 뒤 개발 시작 |
| 발주·납기 범위 확대 요구 | 조회 전용으로 제한하고, 입고·잔량은 별도 검토 |

| 알림 기준 불명확 | 기준일·수신자·반복 규칙을 설정값으로 분리 |

## 13. 미팅에서 확인할 사항
- 관리하는 계약·인증 종류와 각각의 갱신 절차·소요 기간
- 만료 알림 기준일(D-90·30·7이 적절한지), 수신자, 채널
- 갱신 업무를 누가 책임지고, 완료를 무엇으로 판단하는지
- 자동연장·무기한 계약이 있는지
- 담당 부서와 역할별 조회 범위
- 비식별 샘플 제공 가능 여부, 사업자번호 저장 가능 여부
- 발주·납기를 어느 수준까지 원하는지, ERP 사용 여부
- 배포 환경과 보안 제약
