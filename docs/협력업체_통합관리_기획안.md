# 협력업체 자료 및 업무 통합관리 프로그램 기획안

> 개인 제안 초안. 개발 범위와 역할은 팀 미팅에서 확정한다.

## 1. 배경과 문제
협력업체 계약서·인증서·발주·납기 자료가 엑셀, 이메일, 공유폴더 등에 분산되어 자료 검색, 최신본 확인, 기한 추적에 반복 업무가 발생한다. 실제 발생 빈도와 영향은 업무 담당자 인터뷰로 검증한다.

## 2. 목표와 대상
구매·품질·생산 등 내부 담당자가 업체별 자료와 진행 상태를 함께 확인하고, 미처리 업무를 찾아 처리할 수 있도록 한다. 주 사용자와 계약인증의 정확한 의미는 미팅에서 확인한다.

## 3. 첫 버전 범위
- 업체 기본정보와 내부 담당자 등록·조회
- 계약서·인증서 업로드 또는 원본 링크 등록
- 문서 종류, 버전, 검토 상태, 유효기간 관리
- 발주번호, 품목, 수량, 요청 납기와 확정 납기 관리
- 부분 입고 수량 및 미입고 잔량 기록
- 인증 만료 예정, 납기 미확정, 지연 업무 현황판
- 업무별 담당자, 처리 기한, 완료 상태와 변경 이력

이메일 자동 수집, ERP 실시간 연동, 외부 업체 포털, 자연어 질의는 후속 확장으로 검토한다.

## 4. 핵심 사용 흐름
업체 등록 → 인증서 등록·검토 → 발주 등록 → 업체 납기 확정 → 부분 입고 또는 입고 완료.
인증 만료 예정이나 납기 미확정 건은 담당자 업무 목록에 표시하고 처리 결과를 기록한다. 발주 변경 시 납기 재확인 대상으로 표시한다.

## 5. AI와 자동화
문서에서 업체명·문서번호·유효기간 등을 추출하는 기능은 확장 단계에서 추가한다. 원본과 추출값을 함께 표시하고 사용자가 확인한 뒤 확정한다. 업체를 식별하지 못하거나 값이 모호하면 확인 대상으로 남긴다.
만료일 비교, 미회신 판정, 납기 지연 판정은 명시적인 규칙으로 구현한다. 알림의 중복 방지, 완료 조건, 재알림 기준을 정의한다. 외부 발송과 납기 확정은 담당자가 수행한다.

## 6. 개발팀 3명 역할 분담안
| 담당 | 책임 | 주요 산출물 |
|---|---|---|
| 1. 화면·사용 흐름 | 업체·문서·발주 화면, 검색, 현황판, 입력 검증 | 화면 설계 및 프론트엔드 |
| 2. 서버·데이터 | DB, API, 파일 저장, 로그인·권한, 변경 이력 | 데이터 모델 및 서버 |
| 3. 자동화·자료 연동 | 엑셀 가져오기, 만료·지연 점검, 알림, 후속 AI 추출 | 자동화 작업 및 연동 기능 |

공통으로 업체·발주·문서 ID, 상태 정의, 날짜 형식, API 규격을 합의한다. 담당 2가 데이터 구조 변경을 조율하고, 각 담당자는 구현 기능의 검증을 책임진다. 배포와 전체 흐름 검증은 공동 수행한다.

## 7. 개발 단계
1. 요구사항 확인: 실제 업무 사례, 익명화한 자료 샘플, 기존 시스템 조사.
2. 기반 구현: 공통 데이터 구조, 업체 관리, 파일 저장, 기본 화면 연결.
3. 업무 구현: 문서·발주·입고 기능과 담당자 업무 목록 연결.
4. 자동화 구현: 만료·지연 점검, 알림 및 엑셀 가져오기.
5. 검증: 실제 샘플로 전체 흐름 시연, 사용자 피드백 반영.

기간과 비용은 자료 형식, 팀 숙련도, 연동 및 배포 조건 확인 후 산정한다.

## 8. 완료 기준과 검증
- 업체 등록부터 입고 완료까지 같은 발주 건으로 시연 가능.
- 부분 입고와 수량 변경 시 미입고 잔량이 정확하게 반영됨.
- 만료 예정, 납기 미확정, 기한 초과 건이 합의한 규칙대로 표시됨.
- 담당자 변경, 문서 수정, 납기 변경 이력 확인 가능.
- 권한이 없는 사용자는 문서와 업무 정보를 열람하거나 수정할 수 없음.
- 자료 검색 시간과 누락 발견 건수를 시범 사용 전후 비교하며 목표 수치는 사전 측정 후 합의.

## 9. 대안 방향
| 방향 | 적합한 상황 | 첫 시연 | 확인할 조건 |
|---|---|---|---|
| 문서 통합 검색 | 자료 찾기와 최신본 확인이 가장 어려움 | 업체 검색 후 검토된 문서 열기 | 원본 위치, 최신본 기준 |
| 업무 누락·기한 관리 | 확인·독촉·후속 조치가 빠짐 | 만료 예정 업무 생성과 완료 처리 | 담당자, 기한, 완료 조건 |
| 협력업체 제출 포털 | 자료와 납기 회신 수집에 시간이 많이 듦 | 업체 제출 후 내부 검토 | 외부 접근 권한, 업체 참여 |

첫 미팅에서는 위 방향 중 가장 큰 문제를 해결하는 하나를 선정한다.

## 10. 미팅 질문 및 답변 방향
| 예상 질문 | 답변 또는 확인 사항 |
|---|---|
| 엑셀로도 가능한가? | 여러 자료 사이의 중복 입력과 확인 누락 사례를 먼저 검증한다. |
| AI가 꼭 필요한가? | 기본 업무 흐름은 일반 프로그램으로 구현하고 문서 입력 보조에 AI를 활용한다. |
| AI 오류는 어떻게 처리하나? | 원본 대조와 사용자 확인 후 확정한다. |
| ERP와 중복되지 않는가? | ERP 기능을 조사하고 기존 기준 데이터를 정한 뒤 보완 범위를 결정한다. |
| 3명이 구현할 수 있는가? | 하나의 업무 흐름을 우선 완성하고 연동과 포털은 단계적으로 확장한다. |
| 개발 기간과 비용은? | 샘플·연동·보안 조건을 확인하고 시연용과 실사용 범위를 나눠 산정한다. |
| 효과는 어떻게 측정하나? | 검색 시간, 누락 건수, 납기 미확정 건수 등을 비교한다. |

### 반드시 확인할 사항
- 최근 자료 분산 때문에 문제가 생긴 실제 사례는 무엇인가?
- 검색·입력·확인·독촉 중 시간이 가장 많이 드는 업무는 무엇인가?
- 계약인증은 계약서·인증서 관리인가, 계약 승인·검증 절차인가?
- 최종 기준으로 사용하는 시스템이나 파일은 무엇인가?
- 익명화한 자료 샘플을 받을 수 있는가?
- 시범 사용 담당자와 개발 기간은 누구와 어떻게 정하는가?
- 회사 자료의 외부 AI 서비스 전송이 허용되는가?
